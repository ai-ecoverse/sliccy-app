Capture-wide unique-slice/platform integration, source proposal

This round includes the accepted no-root BSD source, its additional boundary coverage, removal of the unused proof ACL helper, the common pathname slice binder and counted receipts. The production audit-token/guest-derived-static verifier is unchanged. All new code is gated by SLICCY_CAPTURE_RUNNER_PROOF. No identity root child, staging or sudo is in the capture path. Signed-app-only TCC install/removal remains the sole authorized root step. Historical signed artifacts, source freezes and outcomes remain unchanged.

Every current proof role uses ScreenRunnerSliceBinding: app self, helper, Chrome, osascript, system owners, WindowServer and the released CLI's proof-only owned-process checks. No role uses a default pathname CDHash as its expected running hash. Pre-spawn checks produce an ordered, fully validated catalogue of all parsed architecture slices. The first live check selects the unique same-type CDHash match and pins its actual running hash. Later live, copy and signal checks retain that pin. Exact artifact/helper/CLI hashes and designated role requirements remain separate constraints.

The common binder requires positive PID; fresh before/after incarnation/control receipts; exact role requirement; dynamic validity; kernel path/hash; Apple platform bit for system owners, SecurityAgent and osascript; live hash equal to csops hash; canonical retained-FD file sample; exactly one parsed CPU/subtype slice with matching hash type and CDHash; returned CodeOffset equal to the parsed offset; selected full static validity and identity recheck; fresh dynamic/live/kernel/path/incarnation equality; and repeated retained-FD/path device/inode/size/mtime/ctime equality. Full digest must contain the compared CDHash as its 20-byte prefix. Zero, multiple or wrong-type matches refuse. Explicit native attributes are CPU and subtype only, never a trusted arbitrary offset. Thin/fat32/fat64 byte parsing bounds files to128MiB and1..8 nonoverlapping, unique CPU/subtype slices.

Apple roles use exact anchor apple plus signing identifier and platform status. Developer ID roles preserve their exact identifier/team/Developer ID requirement. Non-Chrome selected slices require flags25 status0 and dynamic16 status0. Chrome preserves the separately approved exception only: exact Google Developer ID requirement/EQHXZ8M8AV, full bundle flags9 identity first, strict25 evidence next, guest-static0, dynamic0; selected explicit slice flags9 must succeed before25 may be0 or-66999. No other role tolerates detritus. Existing full-bundle/guest checks are retained, rather than substituted by a slice check.

This binds running kernel-enforced signed code to one signed slice in the sampled pathname file. It does not prove the executing text vnode or which vnode supplied the pages. File/identity observations are bracketed samples, not an atomic cross-process transaction or protection against concurrent privileged mutation. Unknown, denied, unstable or oversized evidence refuses.

BSD selection is unchanged: actual fixed self/direct-parent controls agree on seven fields before an EPERM/zero-byte proc result may use sysctl. Readable proc must match its target sysctl bracket. WindowServer requires both control gates, stable PID/PPID1/start and the full eUID88/rUID0/sUID0 tuple. Actual resolver-to-code-to-inventory synthetic tests cover disagreement, instability, tuple and code refusal. No historical incarnation is substituted for current data.

Code-binding receipt fields are role, site, passed(boolean), step(fixed enum), statuses(ordered flag/status pairs), selected(null or [CPU,subtype,offset decimal,size decimal,hashType,CDHash base64,fullHash base64]), and compared. Compared contains requested PID, exact requirement, expected hash/catalogue, complete before/after incarnation and control values, kernel path/hash/flags, live digest, retained file metadata, all slice members and operation receipts. Operation IDs1..8 are requirement,guest,guest-static,information,open,explicit-static,kernel,incarnation. Each operation row is [ID,status,valuePresent], with an information-table index appended for information results. The deduplicated information table retains actual hash,path,identifier,full identity and offset values before any comparison, including refused values; -1 in valuePresent means unavailable generic failure status, never fabricated success. Native Security failures preserve fixed API name/status/non-null evidence. Validity flags/statuses retain actual returned values. Missing intermediate outputs on refusal remain absent, never inferred.

Aggregation is mandatory for code-binding and bsd-identity receipts. Its equality key is the complete canonical sorted JSON of all fields, compared byte-for-byte, including every role/site/PID/start/hash/type/slice/requirement/status and all control observations. No time or count participates in identity equality. A SHA256 receiptKey identifies that full canonical receipt on the wire; it is not a replacement for byte equality inside the ledger. Changed values and every refusal emit a new full row immediately, even when a prior key was seen. The independent parser must reject a receiptKey reused for different canonical bytes.

A full row adds receiptAggregate:false, receiptKey, receiptCount1 and firstEventElapsedMs==lastEventElapsedMs for that actual observation. Identical subsequent receipts are counted; their flush row carries only receiptAggregate:true, receiptKey, receiptCount and first/last actual event times in addition to the ordinary journal envelope. Counts describe subsequent observations only, so adding full and aggregate counts does not double-count the first observation. A consumer must have the corresponding complete receipt before resolving an aggregate. Checks still execute at every original call/refresh. No decision reads the ledger or its output.

Changed keys flush that stream's pending repetitions first. Refusal flushes all pending streams then writes the complete refusal. Every fixed cause callback flushes all pending receipts, as do cancellation, inventory failure and source-monitor failure. Final finish flushes all before terminal, forbids further records and fails closed if any delivery remains in flight; it never waits on an output sink. All callbacks, including loss, occur outside owner and ledger locks. Delivery remains synchronous to the existing bounded/nonblocking journal; no unbounded queue or executor is introduced. The owner evidence batch retains its four-row per-kind bound and retires authority without partial success on loss.

Bounds are256 receipt streams,100000 pending identical repeats,3584 bytes canonical receipt fields,4096 bytes per actual NDJSON row and1048576 bytes per case. The512-byte field-envelope allowance does not bypass the actual row-size check. Overflow, malformed input/numeric booleans, late rows, incomplete final delivery or journal loss retire authority. Terminal success requires complete delivery. A high number of owners or changed identities may fail the diagnostic budget despite source-count bounds; it cannot silently omit rows.

Tests/RunnerSlice/volume.py records both uncompressed and aggregated calculations. Stable receipt volume is independent of refresh count, but existing nonreceipt rows still consume the shared cap. Its nominal model uses42 inventories/refreshes,47 receipt streams,8 flush opportunities,512-byte legacy Chrome rows and32KiB other-row allowance. It also reports the full45s/initial-retry envelope including unchanged legacy rows, whose margin may be negative; that is a named diagnostic refusal, not a guarantee that every admissible source universe fits. The coordinator-authorized proof-only journal cap is now1MiB; every other bound is unchanged. Actual byte counts always govern. The model is planning evidence, not a native capture result.

Validation is hosted only. Fabricated structs/bytes and injectable actual Swift boundaries exercise code without native process/Security queries. Foundation attribute/record construction is separate from real Security execution. Every mutation must compile successfully and fail the selected assertion at runtime, with exact source restoration and a green restored test. Native query/GUI/root/TCC/capture execution is outside this test job. Both source reads, build13 signing, immutable artifact verification, independent driver/schema/wrapper read, independent authorization purpose evidence and coordinator capture permission remain required. Physical stopCapture can still wait for the cooperative pool after synchronous output invalidation; issue3 and the original50ms/1500ms limits remain unchanged.

CLI receipt completion delta: the session supplies a mandatory ScreenRunnerChildReceipts sink to ScreenRunnerConnection and the proof-only ScreenChild.runner factory. Capture-build ordinary constructors refuse before launch instead of allowing a missing sink. Non-capture ScreenChild tokens are unchanged after conditional exclusion. All ScreenRunnerProcessIdentity capture/verify/verifyRole sliceEvidence defaults are removed, so direct omission is a compile error.

Initial CLI capture and every actual signal identity check use the same common binder with the required sink. Initial evidence is collected during synchronous verification and delivered on return or throw outside the child lock. Resume/TERM/KILL/deinit signal verification uses the shared owner-lock batch; every output/loss callback occurs after unlock. Already-reaped stop skips the check as before. No signal or identity policy is widened. Each invoked child boundary also emits a fixed child-initial or child-signal receipt, with child-complete or child-refused, covering a refusal before the binder can be reached. These boundary receipts have selected:null and statuses:[]; they do not claim a native code check when none ran. Compared includes actual PID, signal or null, and recorded incarnation/hash when present. Binder receipts retain their complete native comparisons independently.
