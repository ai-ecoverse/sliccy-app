Capture identity source proposal, based on fa4ad8c build12

This source change is held for both acceptance reads. No signed build, native identity invocation or capture is authorized by this file. The capture-wide explicit unique-slice and platform-policy integration is the next source round before build13. Existing guest-derived static checks are retained here, not relabelled as pathname slice binding. The prior prerequisite unique-slice implementation and its evidence remain independent.

The ordinary-user caller samples two fixed controls on every observation: getpid() and getppid(), distinct positive PIDs, with the first control's sampled parent equal to the latter. Each control is sysctl-before, proc_pidinfo, sysctl-after. All seven identity fields must match exactly and every status/byte count/PID/start bound must be valid. The fields are PID, parent, effective UID, real UID, saved UID, start seconds and microseconds. No cached agreement, environment override, supplied PID control, historic incarnation or previous run grants agreement.

The target is sampled sysctl-before, proc_pidinfo, sysctl-after in the same observation. A readable proc sample must match both sysctl samples exactly. Only proc EPERM with zero returned bytes allows sysctl as the source, and only when both control brackets agree. Short results, ESRCH, missing samples, other errors, invalid starts, identity contradictions and unstable samples refuse. The source is sampled again after the existing live/static/kernel code checks. Before and after identities must agree exactly. WindowServer additionally requires control agreement at both observations and the complete tuple parent1/eUID88/rUID0/sUID0. Its PID and full start timestamp must stay equal. The tuple is policy based on authenticated same-run observations, never a cross-run PID/start assertion.

The app's proof-only --runner-kernel entry, root-child implementation and sudo spawn/reap adapter are removed from current Sources. The proof caller no longer requires or launches from a staged root-owned path. The prior root implementation, staging scripts and artifact/evidence stay retained in git and private freezes; staging scripts are historical, unimported by the capture application, and are not a permitted final-wrapper operation. No identity operation runs as root. The separately approved signed-app-only TCC install/removal remains unchanged and is the only authorized root step in the future capture wrapper.

New bsd-identity evidence is bounded by the existing journal and case limits. It carries phase(before|after), requested PID, observation status, fixed self/parent control PIDs, two control brackets and the target bracket; every read carries status/count/expected/value. Available value fields are pid,parent,effectiveUID,realUID,savedUID,seconds(decimal string),microseconds. Unavailable values are null. accepted, usedSysctl and controlsAgreed are actual typed booleans, or null for the latter two on refusal. The event clock is captured immediately after the observation. Output/loss uses the existing nonblocking journal fail-closed path outside owner locks. No success may be inferred from a missing row.

Inventory identity replaces privilegedBracket with sysctlBound and adds realUID and savedUID (nullable for roles whose unchanged identity path does not collect them). WindowServer requires sysctlBound and the whole credential tuple at the actual inventory boundary. Recognition never permits selection; SecurityAgent stays always protected, unknown owners refuse, and authorization purpose correlation remains independently required. kernel-child and kernel-children-cleaned events no longer exist in this caller. The independent schema/driver and final wrapper need an exact new freeze before execution.

Tests use fabricated C structures through the production selection/binding functions and synthetic Swift calls through the real resolver and inventory. Hosted mutations cover the agreement gate, the second control bracket, target stability, EPERM-only fallback, exact byte count, each WindowServer UID, parent, and before/after binding. They must compile and fail with their named runtime assertion; compile failures never count. Swift tests and native synthetic fixtures must only run hosted. No sysctl/proc/Security/GUI query is part of those synthetic tests. Local source/mocked tests alone are not native validation.

No change to capture permission, source selection, role, CDHash pins, authorization purpose, timing limits, cleanup signal authority or production authority is inferred. The next slice-explicit source round must preserve live/kernel equality, exact role/Apple/platform policy, same-type unique slice and flags25 validity with path/device/inode binding before any build13 signing or capture execution.
