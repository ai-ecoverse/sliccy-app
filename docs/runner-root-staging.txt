# Capture proof root staging — source under review

This is a wrapper prerequisite, separate from the proof-only read-only `--runner-kernel` entry. It has not been executed. The integrated source, regression sources and exact wrapper binding require both reads before compilation, signing or dispatch.

The wrapper first verifies the downloaded immutable app and records every bundle file's SHA256, size and executable bit, its directory set, its actual designated requirement and running-architecture CDHash. It retains the original archive and bundle. The copied helper must remain byte-identical to the accepted helper artifact; the stage never signs anything.

The destination is exactly `/Library/SliccyProof-<canonical GitHub run ID>/Sliccy.app`. The wrapper cannot supply another destination. `/` and `/Library` must be root:wheel directories without group/world write permission, symlinks or ACL entries. The new directory must not already exist. Its device/inode are retained for removal. It is root:wheel with an initial mode no broader than 0755; the restrictive umask creates mode0700 until the identity is recorded, then the program sets0755. There is no runner-writable interval.

The root staging program is passed as the exact reviewed source bytes to an already verified root-owned Apple system Python interpreter, using isolated/no-site/no-bytecode options. It is never imported from the workspace as root. Interpreter discovery happens unprivileged, is recorded, and must resolve the actual interpreter rather than elevate a developer-tool locator shim. The resolved interpreter, its framework/standard-library inputs and their ancestors must be immutable to the runner; its Apple identity and bytes are recorded. Missing or unprovable interpreter prerequisites fail staging, with no installation or alternative interpreter. Only fixed hosted assertions reach root. No token, user site, PYTHONPATH, HOME, TMPDIR or PATH override reaches it. The wrapper source must pin this program in its reviewed source map before invoking it.

The staging program opens ancestors and source directories without following symlinks, creates destination entries relative to held directory descriptors using exclusive creation, and never invokes a recursive copy or chown tool. It rejects special files, hard-linked files, set-ID/sticky source modes, unexpected paths, missing paths and source changes. It copies at most 4096 entries/256 MiB, with at most 64 MiB per file and depth 16. Each file starts root-readable only; after its exact expected hash and size match it becomes 0444. Only after all static role, designated-requirement and CDHash checks pass are the manifest-designated executable files changed to 0555. Directories are 0755. No ownership, ACL, resource-fork or extended-attribute metadata is imported from the source. Any inherited destination ACL is a refusal.

Before any subject execution, the root program validates the copy with all-architecture, nested and strict signature checks against both the fixed Developer ID app role and the exact previously verified designated requirement. It records and compares the copied CDHash and designated requirement. A substituted or incomplete source cannot produce a validated stage. The normal, unprivileged proof app is subsequently launched from the staged bundle. Its own executable path must have the fixed staging shape, root-owned non-writable ancestors and no ACLs; it must independently match its running code identity.

Only that staged executable may be supplied to `sudo -n` for `--runner-kernel`. The proof-only C adapter uses fixed posix_spawn arguments, exactly five assertion environment values and CLOEXEC-default file actions: only stdin/stdout pipes and stderr /dev/null are inherited. Native lanes, audit locks and other caller descriptors are not inherited. A dedicated waiter retains the actual owned sudo PID until waitpid confirms its exit; a different verified root PID additionally needs an explicit ESRCH observation. No guessed signal or descendant-reap claim is made. The kernel entry has no staging or removal operation. It accepts exactly one canonical numeric WindowServer PID, checks root and the existing hosted assertions/actual OS and architecture, ignores all other environment variables, and revalidates WindowServer itself. It has a two-second self-alarm. Its hello identifies the root process; the parent independently checks UID, launch-time incarnation, the chain to its retained sudo child, the parent's own designated requirement and its own running CDHash. The root child emits no identity facts until the parent sends its single ACK byte. Missing, conflicting or unavailable evidence leaves WindowServer unbound. The ACK authenticates the result channel; the root-owned stage is what prevents a runner-writable executable from being elevated.

Staging recovery contract (V2)

The root creation identity is sampled immediately after the successful exclusive mkdir and emitted before opening/copying the bundle. Controlled cancellation is deferred only across that short creation/record sequence; stdout is nonblocking. Even a broken creation-record sink enters cleanup with the locally retained inode. Removal attempts diagnostic records but never makes deletion conditional on their delivery. Diagnostic loss still forbids a successful outcome. Failure before any identity can be established is explicitly cleanup-creation-identity-unavailable; the program never guesses an inode or deletes an unrelated existing directory.

The unprivileged adapter consumes stdout incrementally through RecordStream. Each complete validated creation record updates its retained device/inode BEFORE invoking any external logging callback. It keeps complete prefix records if a later row is truncated/malformed, the callback fails, or the invocation times out. A diagnostic callback failure is remembered while draining continues; it cannot block the cleanup action. Raw output must also be retained by the outer envelope before callback parsing. A delivered prefix is recovery evidence, never a valid whole transcript.

The wrapper invoke callback now accepts on_stdout and must deliver actual byte chunks during execution. It must attach settled:true to the result or abnormal exception ONLY after it has confirmed the staging writer's termination and owned process settlement, including any sudo child. The adapter refuses concurrent removal while a writer remains unconfirmed. A missing flag, timeout without settlement evidence, lost creation identity, malformed removal record or unavailable separate confirmation is a named non-PASS with retained identity; no guessed signaling or path-only cleanup is authorized. This callback integration remains part of the subsequent exact wrapper read, not implemented or claimed by this source module alone.

After ANY abnormal creation invocation, with the creation identity and writer settlement confirmed, the adapter performs one SEPARATE fixed remove invocation bound to the retained device/inode. It does so even if the original process reported its own cleanup. If that same directory is already absent, the remover records alreadyAbsent:true with the supplied retained identity; it claims absence, not an independent inode match on a nonexistent object. If a directory exists, its actual inode must match before any deletion. Replacement refuses. Only a complete successful removal transcript clears the adapter's retained identity. If diagnostics then fail, the result is cleanup-diagnostic-loss with removalConfirmed:true, never a successful trial. Any other unconfirmed removal keeps the identity and names the failure. No unbounded retry is introduced.

Uncatchable process death can still occur between filesystem mutation and a complete identity record. That cannot be turned into a confirmed removal: it fails with identity-unavailable and requires disposition, without deleting by guessed path. Controlled timeout/cancellation, partial later output and lost callbacks are covered by the prepared actual-boundary regressions; no test has run under the current source-review hold.
